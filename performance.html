Performance notes: Fashion-MNIST CNN

This document describes how the training speed of the convolutional Fashion-MNIST classifier was improved, which files changed, and what was measured. Paths are relative to the project root C:\Users\dell\Documents\Codex\2026-10-23\nfs.

The first CNN lived in a self-contained file, projects/fashion-mnist/src/main/java/FashionConvNet.java. It had its own convolution, pooling and dense code. Every loop was scalar, and every layer allocated new nested arrays for each image.

3. Step A: Vector API in the convolution

The library's VectorMath class already used jdk.incubator.vector for dense operations. Two range-based primitives were added so that convolution rows can be processed as contiguous SIMD operations, with offsets into both arrays.

Changed file: src/main/java/vector/VectorMath.java

// out[outOff + i] += scalar * in[inOff + i]  for i in [0, n)
public static void axpyRange(float[] out, int outOff, float scalar,
                             float[] in, int inOff, int n) {
    int i = 0;
    int limit = SPECIES.loopBound(n);
    FloatVector vScalar = FloatVector.broadcast(SPECIES, scalar);

    for (; i < limit; i += SPECIES.length()) {
        FloatVector vo = FloatVector.fromArray(SPECIES, out, outOff + i);
        FloatVector vi = FloatVector.fromArray(SPECIES, in, inOff + i);
        vScalar.fma(vi, vo).intoArray(out, outOff + i);
    }
    for (; i < n; i++) {
        out[outOff + i] += scalar * in[inOff + i];
    }
}

// sum over i in [0, n) of a[aOff + i] * b[bOff + i]
public static float dotRange(float[] a, int aOff,
                             float[] b, int bOff, int n) {
    int i = 0;
    int limit = SPECIES.loopBound(n);
    FloatVector acc = FloatVector.zero(SPECIES);

    for (; i < limit; i += SPECIES.length()) {
        FloatVector va = FloatVector.fromArray(SPECIES, a, aOff + i);
        FloatVector vb = FloatVector.fromArray(SPECIES, b, bOff + i);
        acc = va.fma(vb, acc);
    }
    float sum = acc.reduceLanes(VectorOperators.ADD);
    for (; i < n; i++) {
        sum += a[aOff + i] * b[bOff + i];
    }
    return sum;
}

The first version of Conv2D called axpyRange once per output row and kernel tap. That made the vector loop profitable only for wide rows; the 7- and 14-pixel rows of the later layers mostly ran the scalar tail loop. Step C fixes this.

Changed file: src/main/java/layers/Conv2D.java (the stride-1 path is written in step C; the scalar path for other strides is unchanged).

Because the Vector API is incubating, running any class that uses it needs --add-modules jdk.incubator.vector. The compiler configuration in pom.xml already provides it, and the Surefire configuration gained the same argument so that the tests can load the classes.

4. Step B: data-parallel training on four threads

One mini-batch was processed by one thread. The machine has 4 physical cores (8 logical), so the batch was split across replicas of the model.

New file: src/main/java/training/DataParallelTrainer.java

Each worker owns a replica (its own forward and backward caches). For every batch:

  1. The master weights are read once into a flat array (getParameters).
  2. Each replica copies those weights, zeroes its gradients, and processes its contiguous slice of the batch.
  3. The replica gradients are summed in a fixed order (deterministic for a fixed thread count).
  4. The master receives the summed gradients (setGradients) and applies one SGD step.
for (int start = 0; start < count; start += batchSize) {
    int end = Math.min(start + batchSize, count);
    int n = end - start;
    int chunk = (n + threads - 1) / threads;
    float[] params = master.getParameters();

    for (int t = 0; t < threads; t++) {
        final ConvClassifier replica = replicas[t];
        final int from = Math.min(start + t * chunk, end);
        final int to = Math.min(from + chunk, end);
        futures[t] = pool.submit(() -> {
            replica.setParameters(params);
            replica.zeroGrad();
            double loss = 0.0;
            for (int i = from; i < to; i++) {
                int id = order[i];
                replica.forward(images[id]);
                loss += replica.backward(labels[id]);
            }
            return loss;
        });
    }

    Arrays.fill(gradSum, 0.0f);
    for (int t = 0; t < threads; t++) {
        totalLoss += await(futures[t]);
        float[] g = replicas[t].getGradients();
        for (int k = 0; k < g.length; k++) {
            gradSum[k] += g[k];
        }
    }
    master.setGradients(gradSum);
    master.applyUpdate(lr, n);
}

  • src/main/java/layers/ConvClassifier.java: getParameters(), setParameters(float[]), getGradients(), setGradients(float[]). The layout is conv1, conv2, dense1, dense2.

Correctness check: src/test/java/training/DataParallelTrainerTest.java trains one epoch serially and with 3 workers on an odd-sized dataset (37 samples, batch 8) and asserts that all parameters agree within 1e-4.

5. Step C: plane-vectorized convolution and row-major dense layer

5.1 Why the row version was not enough

The profile after step B showed that axpyRange and dotRange were the hot spots, with most time in their scalar tail loops. Feature maps in this network are 28, 14 and 7 pixels wide, and the Vector API's preferred species holds 8 floats. A 7-wide row never reaches the vector loop.

5.2 Padded plane layout

For stride 1, the input is zero-padded once into a buffer with row width wp = inW + 2*padding. Output position (oh, ow) is stored at flat index oh*wp + ow, and kernel tap (kh, kw) reads the input at flat index (oh*wp + ow) + kh*wp + kw. Each tap is therefore a single contiguous operation over the whole output plane. Columns ow >= outW are computed but discarded, which costs a few percent of extra work but keeps every operation long enough for SIMD.

Changed file: src/main/java/layers/Conv2D.java (forwardStride1, backwardStride1).

private float[][][] forwardStride1(float[][][] input, int inH,
                                   int inW, int outH, int outW) {
    int wp = inW + 2 * padding;
    int hp = inH + 2 * padding;
    int planeOut = outH * wp;

    paddedCache = new float[inChannels][hp * wp + kernelW];
    for (int ic = 0; ic < inChannels; ic++) {
        for (int ih = 0; ih < inH; ih++) {
            System.arraycopy(input[ic][ih], 0, paddedCache[ic],
                (ih + padding) * wp + padding, inW);
        }
    }

    float[][][] output = new float[outChannels][outH][outW];
    float[] acc = new float[planeOut];

    for (int oc = 0; oc < outChannels; oc++) {
        Arrays.fill(acc, biases[oc]);
        for (int ic = 0; ic < inChannels; ic++) {
            for (int kh = 0; kh < kernelH; kh++) {
                for (int kw = 0; kw < kernelW; kw++) {
                    VectorMath.axpyRange(acc, 0,
                        weights[oc][ic][kh][kw],
                        paddedCache[ic], kh * wp + kw, planeOut);
                }
            }
        }
        for (int oh = 0; oh < outH; oh++) {
            System.arraycopy(acc, oh * wp, output[oc][oh], 0, outW);
        }
    }
    return output;
}

The backward pass mirrors this. The output gradient is placed in the same padded layout (with zeros in the discarded columns), the weight gradient of each tap is one dotRange over the plane, and the input gradient is one axpyRange into a padded gradient buffer that is cropped at the end.

for (int ic = 0; ic < inChannels; ic++) {
    for (int kh = 0; kh < kernelH; kh++) {
        for (int kw = 0; kw < kernelW; kw++) {
            int shift = kh * wp + kw;
            weightGrads[oc][ic][kh][kw] += VectorMath.dotRange(
                g, 0, paddedCache[ic], shift, planeOut);
            VectorMath.axpyRange(dPadded[ic], shift,
                weights[oc][ic][kh][kw], g, 0, planeOut);
        }
    }
}

Bounds: with planeOut = outH * wp and outH = hp - kernelH + 1, the largest index read is hp*wp + kernelW - 1, so the padded buffer is allocated with kernelW extra elements.

Stride values other than 1 keep the original scalar loops in Conv2D.forward and Conv2D.backward. No network in the project uses them.

5.3 Row-major dense layer

The forward pass of Dense iterated over outputs in the outer loop and over inputs in the inner loop, so it read the weight matrix column by column. It is now row-major, and both passes use the vector primitives.

Changed file: src/main/java/layers/Dense.java (new file in this project; the original dense code was in FashionConvNet.java).

public float[] forward(float[] x) {
    inputCache = x.clone();
    float[] result = new float[out];
    System.arraycopy(b, 0, result, 0, out);
    for (int i = 0; i < in; i++) {
        VectorMath.axpyRange(result, 0, x[i], w[i], 0, out);
    }
    return result;
}

public float[] backward(float[] dOut) {
    float[] dIn = new float[in];
    for (int i = 0; i < in; i++) {
        VectorMath.axpyRange(dw[i], 0, inputCache[i], dOut, 0, out);
        dIn[i] = VectorMath.dotRange(w[i], 0, dOut, 0, out);
    }
    for (int j = 0; j < out; j++) {
        db[j] += dOut[j];
    }
    return dIn;
}

6. Step D: in-place ReLU

ReLU in ConvClassifier allocated a new tensor for every layer on the forward and backward passes. The backward mask only needs the sign of the pre-activation, and ReLU preserves that sign, so the rectified value can be stored in place and used as the mask.

Changed files:

  • src/main/java/activations/Activations.java: new reluInPlace and reluBackwardInPlace for float[][][] and float[].
  • src/main/java/layers/ConvClassifier.java: forward and backward use the in-place versions.
// forward
c1 = conv1.forward(img);
reluInPlace(c1);                    // c1 is now post-ReLU
float[][][] p1 = pool1.forward(c1);
c2 = conv2.forward(p1);
reluInPlace(c2);
float[][][] p2 = pool2.forward(c2);
h1 = dense1.forward(Flatten.flattenChannelsFirst(p2));
reluInPlace(h1);
logits = dense2.forward(h1);

// backward
d = dense2.backward(d);
reluBackwardInPlace(d, h1);         // mask from post-ReLU h1
d = dense1.backward(d);
float[][][] dR2 = pool2.backward(dP2);
reluBackwardInPlace(dR2, c2);
float[][][] dP1 = conv2.backward(dR2);
float[][][] dR1 = pool1.backward(dP1);
reluBackwardInPlace(dR1, c1);
conv1.backward(dR1);

The in-place operations are safe because each conv, dense and pooling output is a fresh array owned by the model, and no caller keeps a reference to it.

11. Remaining opportunities

  • Non-unit stride: Conv2D still uses scalar loops for stride > 1. Not needed by the current network.
  • Evaluation: test evaluation runs single-threaded. It is about 1–3 s, so the benefit is small.
  • Allocation: Dense.forward clones its input for the backward pass, and the flatten and unflatten helpers copy arrays. These are small compared with the convolution.
  • Batch-size effect: batch 512 is not faster than batch 128 in this setup and gives lower accuracy at the same learning rate. Raising the learning rate or training for more epochs would be needed to use it.
  • Fusion: the convolution, ReLU and pooling could be fused into one pass over each plane, which would remove two memory passes per layer.

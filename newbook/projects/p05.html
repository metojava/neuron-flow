Project 5 · Housing price regression

When the answer is a number, not a label

All previous projects predicted a category. This one predicts a price — a continuous value that can be off by $1 or by $100,000, and every error in between is meaningful. That changes everything: no argmax, no threshold, just the distance between prediction and truth.

What the project does

Given 13 neighbourhood and house attributes (crime rate, number of rooms, age, tax rate, and so on), the network estimates the median house value in thousands of dollars. The interesting part is watching predicted values plotted against actual values — a perfect model would be a straight diagonal line, and you can see exactly where the model starts to struggle.

The architecture

int[] topology = {13, 64, 32, 1};

ActivationFunction[] activations = {
    ActivationFunction.linear(),   // 13 normalized features
    ActivationFunction.leakyRelu(0.01f),
    ActivationFunction.relu(),
    ActivationFunction.linear()    // unbounded price estimate
};

NeuralNetwork net = new NeuralNetwork(
    topology, activations,
    LossFunction.meanSquaredError(),
    new Adam(0.001f),
    42L,
    WeightInitializer.heNormal());
The output must be linear. A sigmoid or softmax would clamp predictions to a fixed range and squash the whole price scale into it. A linear neuron can output any real number — exactly what a regression target is.

Normalizing the targets too

// z-score every feature column: (x - mean) / std
for (int c = 0; c < 13; c++) {
    float mean = columnMean(trainX, c);
    float std  = columnStd(trainX, c, mean);
    for (float[] row : trainX) row[c] = (row[c] - mean) / std;
    for (float[] row : testX)  row[c] = (row[c] - mean) / std;  // reuse train stats
}

// targets scale matters: MSE on raw $30,000 values gives huge gradients
float tMean = columnMean(trainY, 0);
float tStd  = columnStd(trainY, 0, tMean);
scale(trainY, tMean, tStd);
scale(testY,  tMean, tStd);

net.fit(new Trainer(200, 32, true, 42L), trainX, trainY);

Never compute statistics from the test set — reuse the training mean and standard deviation, otherwise information leaks from test into training.

Prediction vs actual

System.out.println("   actual   predicted    error");

float sumSq = 0f;
for (int i = 0; i < testX.length; i++) {
    float pred = net.predict(testX[i])[0] * tStd + tMean;  // un-scale
    float real = testY[i][0] * tStd + tMean;
    sumSq += (pred - real) * (pred - real);

    if (i % 20 == 0) {
        System.out.printf("%9.1f %10.1f %8.1f%n", real, pred, pred - real);
    }
}

System.out.printf("RMSE: %.1f ($K)%n",
    (float) Math.sqrt(sumSq / testX.length));

Expected output

   actual   predicted    error
     24.0       25.1      1.1
     21.6       20.4     -1.2
     34.7       33.8     -0.9
     50.0       45.3     -4.7
     19.4       20.8      1.4

RMSE: 3.4 ($K)

Plotting the pairs shows a tight diagonal band for houses under $35k and a widening spread at the top — the model regresses toward the mean because extreme prices are rare in the training data. MSE amplifies those large errors, which is why the curve bends there first.

What you learn from this project

  • Regression heads — linear output + MSE, and how to invert normalization to report real-world numbers.
  • Why normalization is mandatory — features with large ranges dominate the gradient; scaled input converges in a fraction of the epochs.
  • RMSE as a readable metric — "typically off by $3,400" is a statement you can judge; a loss of 0.118 is not.
  • Choosing a robust loss — swapping in HuberLoss.of() reduces the influence of outlier houses and tightens the top of the range.

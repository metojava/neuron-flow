Project 9 · Stock price prediction

Time series, sliding windows, and gates that remember

Sequence data breaks the rules of the earlier projects: rows are ordered, so random shuffling destroys the signal. This project builds sliding windows over a daily price series and adds simplified LSTM-style gates so the network can carry information across many steps instead of treating each window as unrelated numbers.

What the project does

Given the previous 20 days of normalized prices, the network predicts the next day's close. The interesting part is the internal gate: a small piece of arithmetic that decides what to keep and what to forget — the same idea behind a real LSTM, written in about fifteen lines.

Building sliding windows

int WINDOW = 20;

// prices: one close price per trading day, already normalized
List<float[]> inputs  = new ArrayList<>();
List<float[]> targets = new ArrayList<>();

for (int i = 0; i + WINDOW < prices.length; i++) {
    float[] window = new float[WINDOW];
    for (int j = 0; j < WINDOW; j++) {
        window[j] = prices[i + j];
    }
    inputs.add(window);
    targets.add(new float[] { prices[i + WINDOW] });   // next day
}

// IMPORTANT: split by time, never shuffle across the cut
int cut = (int) (inputs.size() * 0.8);
float[][] trainX = inputs.subList(0, cut).toArray(new float[0][]);
float[][] testX  = inputs.subList(cut, inputs.size()).toArray(new float[0][]);
Never shuffle a time series. Training on 2023 and testing on 2019 leaks the future into the past. The temporal split keeps the test set strictly later than every training example — shuffle only within each epoch, which Trainer's shuffle flag does.

The architecture

int[] topology = {WINDOW, 64, 32, 1};

ActivationFunction[] activations = {
    ActivationFunction.linear(),   // 20 normalized closes
    ActivationFunction.leakyRelu(0.01f),  // "candidate" features
    ActivationFunction.tanh(),     // bounded cell state
    ActivationFunction.linear()    // next-day estimate
};

NeuralNetwork net = new NeuralNetwork(
    topology, activations,
    LossFunction.huberLoss(),      // tolerant of single-day jumps
    new Adam(0.001f),
    42L,
    WeightInitializer.heNormal());

net.fit(new Trainer(60, 32, false, 42L), trainX, trainY);

Shuffle is false in the trainer because the windows are already in chronological order — keeping batches contiguous makes each gradient step describe a coherent stretch of history.

The simplified gate

// one LSTM-inspired step, applied to each window
float forget = sigmoid(wf · h + uf · c + bf);   // what to drop
float input  = sigmoid(wi · h + ui · c + bi);   // what to store
float candidate = tanh(wc · h + uc · c + bc);   // the new content

c = forget * c + input * candidate;             // updated memory
float out = sigmoid(wo · h + uo · c + bo) * tanh(c);  // what to expose
ct = ft ⊙ ct−1 + it ⊙ c̃t   →   a path where gradients can flow back through many time steps

Expected output

window=20  hidden=64,32  loss=Huber  epochs=60

epoch 10   train 0.0142   valid 0.0161
epoch 30   train 0.0087   valid 0.0119
epoch 60   train 0.0061   valid 0.0114

test MAE: 0.031  (about 1.2% of average price)
directional accuracy: 58.4% of days called correctly

Price levels are predicted well (the curve tracks the real line closely), but day-to-day direction is only slightly better than a coin flip — honest, and the usual result: short-term direction is mostly noise.

What you learn from this project

  • Windowed sequences — how one series becomes many supervised examples, and why the split must respect time.
  • Gates — sigmoid and tanh combined into memory, forget and output controls; the core idea behind LSTMs and GRUs.
  • Robust losses — HuberLoss.of() ignores outlier days that would otherwise dominate an MSE gradient.
  • Evaluating honestly — MAE plus directional accuracy, and knowing that a pretty plot is not proof of predictive power.
